SECTION 1: THE ULTIMATE 6-MODULE FORMULA, METRICS & ARCHITECTURE CHEAT SHEET High-Yield Exam Summary
📐 MODULE I: SOFTWARE PROCESS & AGILE DEVELOPMENT CHEAT SHEET MODULE I SUMMARY

1. Prescriptive Process Models:
• Waterfall Model: Linear sequential; Communication \(\to\) Planning \(\to\) Modeling \(\to\) Construction \(\to\) Deployment. Inflexible; late working software. Best for compiler/payroll.
• V-Model: Left wing = Verification (Specs/Design); Right wing = Validation (Testing). Early test planning. Best for avionics/medical.
• Spiral Model (Boehm): Risk-driven evolutionary lifecycle in 4 quadrants: (I) Objective setting, (II) Risk analysis/prototyping, (III) Engineering development, (IV) Planning next phase.
• RAD Model: Component-based 60–90 day rapid cycle using 4GL visual tools. Requires modular scope.
• Prototyping: Throwaway (clarify requirements, discard) vs Evolutionary (iteratively evolves into production system).

2. Agile Manifesto & Extreme Programming (XP):
• 4 Values: Individuals & interactions, Working software, Customer collaboration, Responding to change.
• XP Core Practices: Pair Programming (Driver writes code; Navigator reviews in real-time), Test-Driven Development (TDD: write unit tests first), Continuous Integration (CI), 2-week Sprints, On-site customer.

📋 MODULE II: REQUIREMENTS ANALYSIS & SPECIFICATION CHEAT SHEET MODULE II SUMMARY

1. Requirements Classification & IEEE 830 SRS:
• Functional: Specific services/calculations (e.g. "Authenticate user with OTP").
• Non-Functional (FURPS+): Quality constraints: Performance (\(< 2\)s), Security (256-bit AES), Availability (99.99%), Portability.
• IEEE 830 SRS Outline: 1. Introduction (Purpose, Scope), 2. Overall Description (Perspective, Functions, Constraints), 3. Specific Requirements (Interface, Functional, Performance, System attributes).
• Good SRS Attributes: Unambiguous, Complete, Consistent, Verifiable/Testable, Modifiable, Traceable (via RTM).

2. Structured Analysis & Modeling:
• DFD Levels: Level 0 (Context diagram, no data stores) \(\to\) Level 1 (Decomposition into 4–7 sub-processes) \(\to\) Level 2.
• Balancing Rule: Net data flows across parent boundary at Level \(N\) must equal aggregate flows at Level \(N+1\).
• Petri Nets: Places (\(P\), circles), Transitions (\(T\), bars), Arcs (\(A\)), Tokens (\(\bullet\)). Transition fires when every input place has \(\ge 1\) token; consumes input token and deposits output token.
• Data Dictionary Notation: Sequence (`+`), Selection (`[ | ]`), Iteration (`{ }`), Optional (`( )`).

🏗️ MODULE III: SOFTWARE DESIGN & ARCHITECTURE CHEAT SHEET MODULE III SUMMARY

1. Functional Independence: Cohesion vs Coupling:
• Golden Law: Maximize Cohesion, Minimize Coupling!
• Cohesion Hierarchy (Worst \(\to\) Best): Coincidental \(\to\) Logical \(\to\) Temporal \(\to\) Procedural \(\to\) Communicational \(\to\) Sequential \(\to\) Functional (Best).
• Coupling Hierarchy (Worst \(\to\) Best): Content (Worst) \(\to\) Common (Globals) \(\to\) Control (Flags) \(\to\) Stamp (Data structure) \(\to\) Data (Best) \(\to\) Uncoupled.

2. Architectural Styles & Design Heuristics:
• Styles: Data-Centered (Repository/Blackboard), Data-Flow (Pipe-and-Filter), Call-and-Return (Layered), Event-Driven (Pub-Sub).
• Transform Mapping: Maps DFD to Structure Chart: Afferent branch (input) \(\to\) Transform center (compute) \(\to\) Efferent branch (output).
• Fan-Out: Number of directly invoked submodules (\(3 \le \text{Fan-Out} \le 7\)). Fan-In: Number of calling modules (Maximize for reuse).
• Theo Mandel's 3 UI Rules: (1) Place user in control, (2) Reduce user memory load, (3) Make interface consistent.

🧪 MODULE IV: TESTING & MAINTENANCE CHEAT SHEET MODULE IV FORMULAS

1. White-Box Basis Path Testing:
• Cyclomatic Complexity Formulas: \[ \mathbf{V(G) = E - N + 2P = P' + 1 = R} \] where \(E\) = edges, \(N\) = nodes, \(P = 1\) (connected components), \(P'\) = predicate nodes, \(R\) = enclosed regions \(+\) 1 outer region.
• Significance: Defines maximum number of linearly independent paths needed for 100% statement and branch coverage.

2. Black-Box Testing & Levels:
• Boundary Value Analysis (BVA): For range \([a, b]\), test: \(a, \ a+1, \ \text{Nominal}, \ b-1, \ b\).
• Integration Testing: Top-Down (requires Stubs) vs Bottom-Up (requires Drivers) vs Sandwich.
• Maintenance Types: Corrective (21%), Adaptive (25%), Perfective (50% - Largest), Preventive (4%).
• Reengineering Model: Inventory analysis \(\to\) Document restructuring \(\to\) Reverse engineering \(\to\) Code/Data restructuring \(\to\) Forward engineering.

🛡️ MODULE VI: RISK MANAGEMENT & CASE TOOLS CHEAT SHEET MODULE VI SUMMARY

1. Software Risk Management:
• Risk Exposure: \(\mathbf{RE = P \times C}\) (Probability \(\times\) Impact Cost).
• Risk Reduction Leverage: \(\mathbf{RRL = \frac{RE_{\text{before}} - RE_{\text{after}}}{\text{Cost of Action}}}\). (Justified if \(RRL > 1.0\)).
• RMMM Plan: Mitigation (proactive avoidance before risk occurs) \(\to\) Monitoring (tracking early warning triggers) \(\to\) Management (contingency response after risk occurs).

2. CASE Tools Environment:
• Architecture: User Interface Layer \(\to\) Tool Integration Services (Data, Control, Presentation) \(\to\) Object Management System (OMS / Central Repository).
• Taxonomy: Upper CASE (Analysis/Design/DFD/UML), Lower CASE (Compilers, Test automation, Code generators), Integrated CASE (End-to-end full SDLC traceability).

🎯 NUMERICAL 1: White-Box Basis Path Testing & Cyclomatic Complexity FULL 13 MARKS
Find Cyclomatic Complexity \(V(G)\) and derive independent basis paths for:
int findMax(int a, int b, int c) { int max = a; if (b > max) max = b; if (c > max) max = c; return max; }
Step 1: Graph Nodes & Edges

Nodes: \(N = 6\) (Node 1: entry, Node 2: check \(b>max\), Node 3: \(max=b\), Node 4: check \(c>max\), Node 5: \(max=c\), Node 6: return).
Edges: \(E = 7\) (\(1\to 2, \ 2\to 3, \ 2\to 4, \ 3\to 4, \ 4\to 5, \ 4\to 6, \ 5\to 6\)).

Step 2: Cyclomatic Complexity via 3 Independent Methods

1. Edges & Nodes: \(V(G) = E - N + 2P = 7 - 6 + 2(1) = \mathbf{3}\).
2. Predicate Nodes: Nodes 2 and 4 are predicates \(\implies V(G) = P' + 1 = 2 + 1 = \mathbf{3}\).
3. Enclosed Regions: 2 bounded inner regions \(+\) 1 unbounded outer region \(\implies V(G) = \mathbf{3}\).

Step 3: Linearly Independent Basis Paths & Test Suite

• Path 1: \(1 \to 2 \to 4 \to 6 \implies \text{Input } (10, 5, 2) \implies \text{Expected: } 10\)
• Path 2: \(1 \to 2 \to 3 \to 4 \to 6 \implies \text{Input } (5, 10, 2) \implies \text{Expected: } 10\)
• Path 3: \(1 \to 2 \to 4 \to 5 \to 6 \implies \text{Input } (5, 2, 10) \implies \text{Expected: } 10\)

✓ Final Answer: V(G) = 3 | Exactly 3 Independent Basis Paths Guarantee 100% Path Coverage
🎯 NUMERICAL 2: Function Point (FP) Calculation & Language LOC Sizing FULL 13 MARKS
System has: EI: 20 simple (wt 3), 10 average (wt 4); EO: 15 average (wt 5), 5 complex (wt 7); EQ: 12 simple (wt 3), 8 average (wt 4); ILF: 4 average (wt 10), 2 complex (wt 15); EIF: 3 average (wt 7). All 14 complexity factors are rated 3. Compute UFC, VAF, FP, and Python LOC (25 LOC/FP).
Step 1: Unadjusted Function Count (UFC)

\[ UFC = (20\times 3 + 10\times 4) + (15\times 5 + 5\times 7) + (12\times 3 + 8\times 4) + (4\times 10 + 2\times 15) + (3\times 7) \] \[ UFC = (60 + 40) + (75 + 35) + (36 + 32) + (40 + 30) + 21 = 100 + 110 + 68 + 70 + 21 = \mathbf{369} \]

Step 2: Value Adjustment Factor (VAF) & Final FP

\[ \sum_{i=1}^{14} F_i = 14 \times 3 = 42 \implies VAF = 0.65 + 0.01(42) = \mathbf{1.07} \] \[ FP = UFC \times VAF = 369 \times 1.07 = \mathbf{394.83 \text{ Function Points}} \]

Step 3: Estimated Sizing in Python & Java

• Python (25 LOC/FP): \(394.83 \times 25 = \mathbf{9,871 \text{ LOC} \ (9.87 \text{ KLOC})}\).
• Java (53 LOC/FP): \(394.83 \times 53 = \mathbf{20,926 \text{ LOC} \ (20.93 \text{ KLOC})}\).

✓ Final Answer: UFC = 369 | VAF = 1.07 | FP = 394.83 | Python Size = 9.87 KLOC | Java Size = 20.93 KLOC

🎯 NUMERICAL 4: Earned Value Analysis (EVA) Health Audit FULL 13 MARKS
BAC = $200,000, Planned Duration = 12 months. At Month 6: PV = $100,000, EV = $80,000, AC = $95,000. Calculate CV, SV, CPI, SPI, EAC, and ETC.
Step-by-Step Variance & Forecasting Calculations

• Cost Variance: \(CV = EV - AC = 80,000 - 95,000 = \mathbf{-\$15,000}\) (\(CV < 0 \implies\) Over Budget).
• Schedule Variance: \(SV = EV - PV = 80,000 - 100,000 = \mathbf{-\$20,000}\) (\(SV < 0 \implies\) Behind Schedule).
• Cost Performance Index: \(CPI = \frac{EV}{AC} = \frac{80,000}{95,000} = \mathbf{0.842}\) (Only $0.84 of work delivered per dollar spent).
• Schedule Performance Index: \(SPI = \frac{EV}{PV} = \frac{80,000}{100,000} = \mathbf{0.800}\) (Running at 80% planned velocity).
• Estimate at Completion: \(EAC = \frac{BAC}{CPI} = \frac{200,000}{0.8421} = \mathbf{\$237,500}\) (Projected cost overrun: $37,500).
• Estimate to Complete: \(ETC = EAC - AC = 237,500 - 95,000 = \mathbf{\$142,500}\).

✓ Final Answer: CV = -$15k (Over Budget) | SV = -$20k (Behind Schedule) | CPI = 0.842 | SPI = 0.800 | EAC = $237,500
